Idempotency evidence: the same decision, delivered twice, is executed once.

Method: start `python3 stub_receiver.py`, then run the demo script TWICE
against it:
    BOOKLY_WEBHOOK_URL=http://127.0.0.1:8787/webhook python3 app.py --script demo.txt

The second run is a fresh process — new envelope_ids, new uuid4s — but the
same conversations reaching the same decisions about the same orders. Because
the key is sha256(conversation|action|order_id) and nothing else, the second
run's envelopes carry keys the receiver has already seen, and it flags them
rather than executing them again.
