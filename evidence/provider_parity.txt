Every decision field matches, including the idempotency key — which is
sha256(conversation|action|order_id), so an identical key means the two
providers reached the same action on the same order in the same
conversation. A downstream receiver deduping on that key cannot tell
which model ran, and does not need to.

order record. Neither model was asked for it, and neither could have
supplied it: the extraction schema has no amount field.

ONE HONEST OBSERVATION
========================================================================

Reply [6], the knowledge-base miss, is where the two runs diverge most
in substance. The stand-in offers a human agent; gpt-5.4-mini asks for
more detail instead. Both correctly decline to invent an answer, and
no decision changed — but the hosted model dropped an offer the
template makes every time.

That is narration drift, not a policy failure, and it is precisely what
the graded narration rubric proposed on the last slide would catch. It
is also the honest limit of this artifact: it proves the decisions are
provider-independent. It does not prove the prose is.
